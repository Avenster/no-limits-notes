## Architecture decisions

### A. Theme system (foundational, done first)
- **No FOUC approach:** blocking inline `<script>` in `root.tsx` `<head>` reads `localStorage["theme"]` + `localStorage["accent"]` and sets `data-theme` + `data-accent` on `<html>` before paint.
- **Tailwind v4 tokens** in `app.css`: define CSS custom properties under `:root` (light defaults) and `[data-theme="dark"]`, mapped into Tailwind via `@theme inline`. Tokens: `--color-bg`, `--color-surface`, `--color-surface-2`, `--color-border`, `--color-text`, `--color-text-muted`, `--color-accent`, `--color-accent-soft`, `--color-accent-contrast`. This makes `bg-bg`, `text-text`, `text-muted`, `bg-surface`, `border-border`, `bg-accent`, `text-accent` utilities switch with the theme.
- **`ThemeProvider`** context (client): exposes `theme` ('light'|'dark'|'system'), `resolvedTheme`, `setTheme`, `accent`, `setAccent`. Persists to localStorage, re-derives on `prefers-color-scheme` change, updates html attributes.
- **BlockNote** reads `resolvedTheme` from context → `theme={resolvedTheme === 'dark' ? 'dark' : 'light'}` (replaces hardcoded `"dark"`).
- **BlockNote CSS overrides** in `app.css` refactored from hardcoded hex to the CSS var tokens (code bg, text, headings, links, inline code, toolbar bg).
- Replace all hardcoded `bg-[#0a0a0a]`, `text-[#e8e8e8]`, `border-white/[0.08]`, `bg-white/[0.04]` etc. across components with token utilities.

### B. Layout routes (enables global sidebar)
Restructure `routes.ts` from flat to nested layouts. **URLs stay identical.**
```
login, join, create, p/:slug          → standalone full-screen (no sidebar)
layout("layouts/AppLayout.tsx", [     → owns shell + glow + <Sidebar/> + <CommandPalette/> + <Toaster/>
  index → routes/home.tsx
  "home" → component/index.tsx
  "settings" → pages/settings.tsx     → NEW profile/settings
  layout("layouts/GroupLayout.tsx", [
    "group/:groupId" →
      "pages"   → pages/list.tsx
      "pages/:pageId" → pages/note.tsx
  ])
])
```
- **`AppLayout` loader** returns: `user`, `groups` (my-groups), `favorites`, `recentPages`, `themePrefs`. Children read parent data via `useRouteLoaderData("routes/layouts/AppLayout")`.
- **`GroupLayout` loader** returns: current `group` + `pages` tree (moves the page-list fetch out of `note.tsx`/`list.tsx` into the shared parent so the sidebar shows it everywhere). `note.tsx` loader then fetches only the single page.
- **`AppLayout`** renders the shared dark/glass shell + ambient glow (eliminates the copy-pasted `<main className="min-h-screen bg-[#0a0a0a]">` across pages) and the global `<Sidebar/>`.

### C. Sidebar reads parent loader data
`<Sidebar/>` uses `useRouteLoaderData` for both layout ids → gets groups + global (favorites/recent/profile) AND current-group pages. No new context needed for data. Sidebar open/collapse state lives in a small `SidebarProvider` context (so a collapse toggle button in the note header still works).

## Backend changes (one migration)

**`schema.prisma`:**
- `User`: add `preferences Json?` (stores `{ theme, accent }`).
- `Page`: add `cover String?`. (`icon`, `parentId` already exist — just surface them.)
- New `Favorite` model: `id`, `userId String`, `pageId String`, `createdAt`, `@@unique([userId, pageId])`, relations to User + Page.

Migration: `npx prisma migrate dev --name profile_favorites_covers` (from `backend/`).

**Services (`backend/src/services/`):**
- `userStore.js`: `updateUserProfile(id, { name, preferences })`.
- `pageStore.js`: extend `savePageContent` to accept optional `icon`/`cover`; add `restoreRevision(pageId, revisionId)` (snapshot current → Revision, then set content = target snapshot); `listChildren` not needed (client builds tree from parentId in list). Include `icon`, `cover`, `parentId` in `listPagesForGroup` select. Add `toggleFavorite(userId, pageId)`, `listFavorites(userId)`.
- `groupStore.js`: `getGroupsForUser` → include `_count` (pages, members) for homepage stats.
- New query for **recent pages**: top N pages the user/member touched, via `Revision` (group by page, newest).

**Routes:**
- New `routes/user.js` mounted at `/user`: `GET /user/me` (profile + preferences), `PATCH /user/me` (update name/preferences). Extends `/auth/me`-style identity (`req.user`).
- Extend `routes/page.js`:
  - `PUT /group/:groupId/pages/:pageId` body now accepts optional `icon`, `cover`.
  - `POST /group/:groupId/pages/:pageId/revisions/:revisionId/restore` (membership-gated; owner/editor).
  - `POST /group/:groupId/pages/:pageId/favorite` toggle (user-only; 401 for guests), `GET /group/:groupId/pages/favorites`.
- `routes/group.js` `/group/my-groups`: include counts.
